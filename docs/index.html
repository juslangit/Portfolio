01-idea.md · 7 sections

The idea

Problem

Luqman is applying for remote AI full stack roles while his entire public footprint says "3D artist and games technology student". Behance shows 3D work. Two Wix sites from 2023–24 (luqmanh1891.wixsite.com/portfolio and /portfolio1) open with "I'm a Game Technology student at Technical University of Malaysia". A hiring manager skimming for an AI engineer bounces immediately.

Proposed solution

One page that inverts the ordering: AI and full-stack work first, 3D and games second as proof of range. Built as a single HTML file so the repo itself is part of the pitch — a stranger can read the whole thing in one sitting and see that it was written, not generated from a template.

Technical interviewersSomething concrete to ask aboutEach card names the hard part (hand-written STL parser, zero-dependency Node, Python ETL)

  • The 3D × web seam is the moat: web-only candidates can't produce the geometry, 3D-only candidates can't produce the app.
  • Everything on the page is his own work — no downloaded models, no template.
  • The site is its own strongest sample.

Conventions

Code

  • One file. If it ever needs a second, that is a decision worth recording first.
  • No dependencies beyond the Three.js CDN tag and the Google Fonts link.
  • Plain ES5-style JS (var, function) — matches the no-build-step spirit and needs no transpiling.
  • The <script> is divided into numbered, commented sections (1 cursor, 2 magnetic, 3 tilt, 4 reveal, 5 nav, 6 hero 3D, 7 confetti, 8 easter egg). Keep that numbering.

Git

  • Branch: feat/<short-description>
  • Commit: imperative, lowercase
  • Pushing main publishes immediately — check the page renders before pushing
Patterns in use

Verify by rendering, not by reading

When to use: before every push. Why: reading the code missed both real bugs found on 2026-09-12.

CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
# screenshot + console errors
"$CHROME" --headless --disable-gpu --virtual-time-budget=8000 \
  --window-size=1440,1400 --screenshot=/tmp/shot.png \
  --enable-logging=stderr --v=0 file://$PWD/index.html 2>&1 | grep -i CONSOLE
# syntax-check the inline script
python3 -c "import re;s=open('index.html').read();open('/tmp/i.js','w').write(re.findall(r'<script>(.*?)</script>',s,re.S)[-1])"
node --check /tmp/i.js

Testing phone width

Gotcha: headless Chrome clamps its viewport to a 500px minimum, so --window-size=390,... renders at 500 and merely crops the screenshot — which looks exactly like a horizontal-overflow bug. Load the page in a 390px-wide <iframe> from a wrapper page instead, and screenshot that.

Every claim must trace to an artifact

When to use: any time a number or adjective goes on the page. Two invented stats ("100+ students taught", "6+ years") and one overstatement ("a decade of visual craft") were caught and replaced before publishing, with numbers that come from real files: 64,770 lots from the peta-lot-tanah README, 5 sports from referee-for-fun, 0 npm dependencies from claude-chat. He will be asked about these in an interview.

A card with two destinations

Most work cards are one big <a>. A card that also links its project record cannot be, because an anchor may not contain another anchor — those cards are a <div class="work …"> with a .foots row holding both links (the game or repo, and Read the record →). Keep the work class when converting: the hover lift and the reveal animation are attached to it, not to the tag.

Record links point at https://luqman-docs.netlify.app/<project>/ — see global/conventions.md → "Documentation is a website".

Portfolio sync — when a project changes
Luqman's standing rule, set 2026-09-12: whenever a project is created or updated, or anything else relevant changes, the portfolio gets updated too.

A PostToolUse hook (~/.claude/hooks/portfolio-sync-reminder.sh, wired in ~/.claude/settings.json) fires whenever _index/projects.md is written, which is exactly when a project is created or changes status. It injects this checklist back into the session. The hook covers the mechanical trigger; the cases below that it cannot detect are on you to catch.

The checklist

What changedWhat to check in index.html

Rules that apply to every sync

  1. Every number traces to a real artifact (D-003). Never invent a stat to fill a card.
  2. Positioning is fixed (D-001): AI full stack leads, 3D supports. A new 3D project does not get promoted above the code work.
  3. Ask before dropping a featured card. Adding is a judgment call; removing something Luqman chose is his decision.
  4. Verify by rendering before pushing — see the pattern above.
  5. git push on main publishes to GitHub Pages immediately.

Getting an image

In order of preference:

  1. Render the thing itself headless — this is how print-quote, peta-lot-tanah and tuition-lms were done. Add --enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader whenever the page uses WebGL, or the canvas comes out blank.
  2. An existing screenshot in the project repo (docs/, press/, dev/ref/screens/).
  3. The Behance cover — see 07-references.md.
  4. A typographic tile (.shot.tile) when there is genuinely no image. Never fake a screenshot.

Then normalise it:

sips -Z 880 shot.png                                     # longest side 880px
sips -s format jpeg -s formatOptions 82 shot.png --out img/slug.jpg

sips -c crops from the centre, not the top — to capture just the top of a page, re-render at a shorter --window-size instead of cropping.

Rendering image cards (Behance, or anywhere text must ship as an image)

Behance has no usable write API and its project body is image modules, not text — so a description can be delivered as a rendered card instead. The generator is ~/.claude/knowledge/projects/portfolio/assets/make_cards.py (copy kept alongside the scratch original); output goes to ~/Desktop/project/web/portfolio/behance-cards/, which is git-ignored because it is an upload deliverable, not part of the site.

Design of the series: 1400px wide (Behance's display width), cool near-black #101319, periwinkle accent #93a6ff tying back to the portfolio's lilac family, Archivo 800 titles / Source Serif 4 body / JetBrains Mono labels. Each card is a composite: the project's own hero image on top, then eyebrow, title, full description, Role, Tools and the signature block — so one upload replaces a whole project post.

Pick the hero by looking, not by position. The first module is often a title slide or a raw screenshot of SketchUp/Blender with every panel showing — six of twelve were, on 2026-09-13. Download every module, lay them out as a contact sheet (an HTML grid screenshotted with Chrome does it in one look), then choose. A software screenshot can be rescued by cropping the viewport out of the chrome — but measure the crop on the exact image you are using, since module layouts differ; a box measured on a sibling screenshot left a strip of UI on both edges. When a project genuinely has no artwork, ship the card with no hero rather than a title card.

Where the hero images come from. Behance serves project images at mir-s3-cdn-cf.behance.net/project_modules/<bucket>/<hash>.<ext>; the 1400 and fs buckets are full quality, while the profile grid only exposes max_808 covers. Pull the module URLs out of a saved project page in document order — the first is usually the intended hero. Exception: the handheld console's four modules are all Tinkercad screenshots; its only photograph of the finished device is the project cover, whose largest form is projects/original/<hash> at 810x1080 (the other size buckets 302-redirect). Sources are archived in assets/hero/.

Never upscale the hero. An image at least 1400 wide goes full-bleed; anything narrower sits centred at its native size on the dark ground. Stretching an 810px photo to 1400 is visibly soft, and the letterbox reads as deliberate on a dark card.

Give the hero explicit width/height attributes so page height is deterministic before the image loads — otherwise the measurement below races image decoding.

The part worth remembering — measure, don't guess the height. A fixed canvas height leaves a dead gap under short text and clips long text. Render twice:

# pass 1 - let the page report its own height once webfonts have settled
#   in the page:  document.fonts.ready.then(() => document.title = "H"+
#                   Math.ceil(document.body.getBoundingClientRect().height)+"H")
chrome --headless --virtual-time-budget=12000 --window-size=1400,400 --dump-dom file://card.html
#   then parse <title>H(\d+)H</title>
# pass 2 - shoot at exactly that height
chrome --headless --hide-scrollbars --force-device-scale-factor=1 \
       --virtual-time-budget=12000 --window-size=1400,<measured> \
       --screenshot=out.png file://card.html

--force-device-scale-factor=1 keeps the pixel size honest; document.fonts.ready is required or the height is measured against the fallback font and comes out short.

Testing interactive JavaScript headlessly

node --check only catches syntax. For anything with a state machine — the Line Call game, the easter egg — drive it and assert on the result.

requestAnimationFrame does not run under --dump-dom (0 frames in 1.5s; 1 under --headless=new), even though setTimeout advances fine with --virtual-time-budget. Shim it in the harness, before the code under test starts its loop:

window.requestAnimationFrame = function(fn){
  return setTimeout(function(){ fn(performance.now()); }, 16);
};
window.cancelAnimationFrame = clearTimeout;

Only frame pacing is faked — the real state machine, maths and scoring all run. Write the harness as a copy of index.html with a driver appended before </body>, have it push findings into an array and end with document.title = "@@" + log.join(" | ") + "@@", then read it back with --dump-dom | grep -o '@@.*@@'. Delete the copy afterwards.

IntersectionObserver callbacks do not re-fire on scroll in that mode, so anything gated on visibility cannot be exercised headlessly — test those branches by calling the code path directly, and check them by hand in a real browser.

For visual checks use --screenshot, which does drive rAF.

06-decisions.md · 4 sections

Decisions

D-001 — Lead as an AI full stack developer, not as a 3D artist
  • Date: 2026-09-12
  • Status: active
  • Context: Luqman is targeting remote AI engineering roles, but every public profile he has leads with 3D art and games. A visitor forms an opinion about which role he is for within about five seconds.
  • Options considered:
OptionProsCons
A — AI full stack first, 3D as the edgeMatches the jobs he is applying forHides his strongest visual work below the fold
B — Hybrid "3D × AI creative tech"Rare, memorable profileMuch narrower job pool
C — 3D artist firstStrongest immediate impressionWorks directly against the career target
D — Landing screen: "code or art?"Serves both audiencesDouble the work, dilutes the positioning
  • Decision: A.
  • Reason: The portfolio's job is to win a specific kind of interview. The 3D work still appears, reframed as the thing that makes him unusual among web candidates rather than as the headline.
  • Consequences / trade-offs: The Behance work is demoted to a supporting section and one outbound link.
  • Reversible? easily — it is ordering and copy
D-002 — One self-contained HTML file, no build step
  • Date: 2026-09-12
  • Status: active
  • Context: Needed a structure for the site.
  • Options considered:
OptionProsCons
A — single index.htmlNothing to install or break; the repo is readable end to endOne long file
B — split html/css/jsEasier for Luqman to edit one concern at a timeThree files to keep in sync, no real gain at this size
C — multiple pagesRoom to growFull reloads, more to maintain
D — Next.jsScalesA build step and dependencies for a page with no data
  • Decision: A.
  • Reason: The repo is part of the pitch. A hiring manager who opens it sees one readable file with no generated code, which is stronger evidence than a scaffolded project. It also means the site cannot break from a dependency update.
  • Consequences / trade-offs: Adding real case studies later will likely force a revisit — that is the trigger to reconsider.
  • Reversible? with difficulty once content grows
D-003 — Every number on the page must trace to a real artifact
  • Date: 2026-09-12
  • Status: active
  • Context: The first draft carried "100+ students taught" and "6+ years making things". Neither was sourced from anything — they were plausible-sounding filler. Luqman's stated requirement is that the portfolio survive a technical interview from strangers.
  • Decision: Replace unsourced figures with ones that point at a file: 64,770 cadastral lots (peta-lot-tanah README), 9 shipped projects (countable in the knowledge base), 5 sports (referee-for-fun), 0 npm dependencies (claude-chat). "A decade of visual craft" was cut to "years" — he graduated in 2024.
  • Reason: An invented number is a trap that springs during an interview. A sourced one is a conversation opener. "0 npm dependencies" is also a better engineering signal than a headcount.
  • Consequences / trade-offs: The stat row is less flattering and more specific.
  • Reversible? easily, but should not be
D-004 — Recover content from the abandoned Wix sites rather than starting blank
  • Date: 2026-09-12
  • Status: active
  • Context: Two Wix portfolio sites exist from 2023–24. Both are client-rendered, so the published HTML contains no readable text.
  • Decision: Read the page models directly from Wix's static asset host (siteassets.parastorage.com/pages/pages/thunderbolt?...&pageId=<pageJsonFileName>.json, where the filenames come from the pagesMap in the served HTML) and extract the text.
  • Reason: Recovered his real 2024 bio and seven forgotten project names (Toki Top, Characters, Master League, Autocat, Madani Makan Mania, Dimanakah Riri?, Flagship Mountain) that would otherwise have been lost.
  • Consequences / trade-offs: Only four of those had recoverable descriptions; the rest are listed with honest generic labels rather than invented ones.
  • Reversible? n/a

How the content was recovered

Wix sites are client-rendered, so the served HTML has no readable text. The page models are fetched separately:

  1. GET the published page; read pagesMap out of the HTML for each page's title, pageUriSEO and pageJsonFileName.
  2. Take the siteassets.parastorage.com/pages/pages/thunderbolt?... URL already present in that HTML and substitute pageId=<pageJsonFileName>.json.
  3. Fetch it (gzip), unescape <, strip tags, and read the prose.

The site list itself comes from the Wix REST API: POST https://www.wixapis.com/site-list/v2/sites/query, with Authorization: $WIX_API_KEY and the wix-account-id: $WIX_ACCOUNT_ID header.

Line Call — a playable card on top of the game work

Luqman asked for a mini game parked on top of the game section. There is no longer a discrete game section — the site is one filterable gallery — so it ships as a .work card with data-cat="game" placed immediately before the Referee For Fun card. It is therefore first under the Game Dev filter and sits on top of the game run under All.

The game: one rule lifted out of Referee For Fun. A shuttle lands near the baseline, the engine knows the margin to the millimetre, and the player has 1.6s to call IN or OUT. On the line is IN. The spread tightens as the streak grows (max(26, 190 - streak*12) mm), so it gets genuinely hard. A lapsed call is scored as a miss, which mirrors the real game's rule that a silent umpire is still a wrong one.

Chosen over re-using the Kedai Runtuh stacker because it is banner-shaped by nature, needs only two buttons, works on touch, and advertises the flagship's actual hook.

Things that had to be got right

  • Keys are bound to the card, not the document. A game that swallows arrow keys on a portfolio page breaks scrolling for everyone who never intended to play.
  • A rally never pauses mid-flight. The first version paused whenever the card left the viewport, which stranded the state machine. It now holds between rallies instead and resumes on scroll-in, so it never serves into an empty room either.
  • The verdict marker draws last. It was being painted before the shuttle, which sat on exactly the same spot and hid it — the one thing the player is looking for.

Verified by playing it, not by looking at it

Drove all three branches headlessly: a correct call (score and streak advance), a wrong call (streak resets, truth and margin shown), and a lapsed call (counted, clock cleared, buttons relocked). This needed an rAF shim — see 04-methods.md; rAF does not run under --dump-dom, which made the game look broken when it was not.
