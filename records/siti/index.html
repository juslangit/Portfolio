01-idea.md · 6 sections

The idea

The problem

Luqman drives regularly and thinks about his projects while driving. Typing is impossible and unsafe, so those thoughts are lost by the time he arrives. He also keeps a detailed knowledge base on his Mac that he cannot reach when away from the desk.

The idea

An assistant he talks to instead of typing to, reachable from his iPhone at any time, that already knows his projects because it reads the same notes Claude reads on his Mac.

Who it is for

Only Luqman. This is a personal tool, not a product to sell. That is why it is protected by a simple PIN rather than real user accounts.

What makes it different from just using an AI chat app

A generic assistant knows nothing about pipeline or retopology. Siti is handed his entire notebook on every request, so he can ask "where did I leave retopology?" and get a real answer.

Not doing

  • No user accounts, no sign-up, no other users.
  • No calendar, email or smart-home control yet.
  • No wake word — he taps once to start the conversation.

2026-09-13 — Siti becomes the main agent

Luqman wants Siti to be the one place he asks for anything, and she makes it for him — not only answers. The first "maker" ability is the 3D asset agent: describe an object → Meshy generates it → retopo-kit cleans it in Blender → pipeline exports it for Unreal. It lives under Siti instead of being its own project. How Siti (in the cloud) reaches Blender (on his computer) is still to be decided.

06-decisions.md · 13 sections

Decisions

2026-09-06 — A web page, not a Siri Shortcut

Chose: a web page opened in Safari. Over: a Siri Shortcut, Telegram voice notes, a WhatsApp bot. Why: Luqman picked it. A Shortcut would be more hands-free, so the page compensates with a listening loop — one tap starts it and it keeps listening until he stops it. Nothing to install and nothing to approve.

2026-09-06 — Send the whole notebook, don't search it

Chose: load all 23 notes into the prompt on every request. Over: vector search over the notes, like mem recall does. Why: the notebook is only about 52 KB. Searching would add a moving part that can return the wrong note, for no benefit at this size. Prompt caching makes the repeated cost small. Revisit if the notebook passes roughly 300 KB.

2026-09-06 — Reuse the existing memory function

Chose: the siti function calls the memory function already in use by mem. Over: talking to the memories table directly. Why: the embedding logic lives in one place. Anything Siti saves while driving appears in mem recall on the Mac, and vice versa.

2026-09-06 — A PIN, not real accounts

Chose: one shared PIN in a request header, checked by the function. Over: Supabase Auth. Why: one user. The PIN's job is to stop a stranger who finds the URL from spending his API credit. Accounts would be a lot of machinery for one person.

2026-09-06 — Claude Opus 5 at low effort

Chose: claude-opus-5 with output_config.effort set to low. Over: a smaller model, or Opus at default effort. Why: in a car, waiting is worse than a slightly less thorough answer. Low effort keeps replies quick while staying on the strongest model. Raise it if answers start feeling shallow.

2026-09-06 — The phone does the speech, not a paid service

Chose: iOS built-in speech recognition and speech synthesis. Over: a transcription API such as Whisper, and a voice API such as ElevenLabs. Why: free, instant, no extra keys, and no audio leaves the phone. The voice is less natural than a paid service — an acceptable trade for a personal tool.

2026-09-11 — Siti is Sky renamed, not a new build

Chose: rename the existing Sky project to Siti. Over: starting a fresh project for Siti. Why: Luqman asked for "an AI persona called Siti, like JARVIS — speak to her on my phone, she replies by speaking, she knows everything I know plus the internet." That is exactly what Sky already was, built 2026-09-06 and never once used because two blockers stopped it. Rebuilding would have thrown away working code to arrive back at the same place. He chose the rename with that stated.

2026-09-11 — Warm and familiar, not formal

Chose: a personality that talks like a friend who knows his projects. Over: the JARVIS register (formal, dry, "sir"), or purely terse answers. Why: he picked it from three options. The formal register costs words on every reply, and words are time when the answer is being read aloud in a car. The rule about staying to two or three spoken sentences still overrides personality — that block in systemPrompt is marked as mattering most.

2026-09-11 — Keep the free phone voice for now

Chose: iOS built-in speech, as before, but preferring a female voice. Over: ElevenLabs, which would sound convincingly human. Why: he chose to spend nothing until the assistant proves it sticks. Revisit once he has actually used her on a few drives. Note the ElevenLabs key is not in ~/.claude/.env anyway, despite global/stack.md listing it as available.

2026-09-11 — SKYBRAIN_* and "Sky AI Brain" keep their name

Chose: rename everything Siti-specific; leave the memory backend alone. Over: renaming every trace of "Sky". Why: "Sky AI Brain" is the Supabase project holding the memories table, and the mem CLI on the Mac reads it through the same SKYBRAIN_* variables. Renaming those would break memory everywhere for a purely cosmetic gain. What did move: SKY_PIN → SITI_PIN (in .env and Supabase secrets), the request header x-sky-pin → x-siti-pin, the function slug, the Netlify site, the GitHub repo, the project folder and sky-sync → siti-sync.

2026-09-11 — Netlify SSO off

Chose: turn off the "require a Netlify login to view" setting. Over: leaving it on and finding another way onto the phone. Why: it was set account-wide, so every site Luqman deploys returned 401 to anyone not logged in — including his phone. It also explains why other published pages were unreachable. The page itself holds no secrets; the PIN checked by the siti function is what actually protects his API credit, which was the design from 2026-09-06.

2026-09-13 — Siti hands "make" jobs to Claude Code on the Todak Academy PC

Chose: Siti writes a job into Supabase; a small helper on the Todak Academy PC picks it up and runs Claude Code headless, which does the actual making. Over: giving Siti one custom tool per ability (Meshy, retopo-kit, pipeline), or a cloud-only flow that calls Meshy and skips Blender. Why: Luqman picked it. Claude Code already drives Blender, Meshy, sfx and Godot, so "ask Siti for anything" works without a new tool per ability, and heavy work runs on his Claude Code plan instead of API credit. He chose the PC over the Mac although the PC is likely off outside work hours — jobs sent then must wait in the queue, not fail.

2026-09-13 — Siti paused: no paid API key

Chose: pause Siti rather than buy Anthropic API credit. Over: paying roughly $10–15/month for the key, or rebuilding her brain on Claude Code on the Todak Academy PC (free, but only works while the PC is on). Why: Luqman does not want to spend money right now. Without the key the edge function cannot answer, search the web, save memories or queue maker jobs, so every Siti feature is blocked. Nothing was deleted: the Netlify page and the Supabase function stay deployed on free tiers and cost nothing while idle. The "main agent" direction and the PC-worker decision above still stand if resumed. Before resuming, fix the notebook size: it is ~760 KB, far past the 300 KB point where sending all of it with each question stops making sense.

Built

  • knowledge table on Supabase, with row level security so only the service key can read it.

  • siti-sync --list shows all 23 notes in Supabase.
