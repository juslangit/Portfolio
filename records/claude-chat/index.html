The idea

Problem

Claude Code only runs on the Mac at home. When Luqman is out — at Todak Academy, travelling — he cannot start or continue work with Claude on any of his projects. He wants to leave the Mac at home and do everything from his iPhone.

Proposed solution

A WhatsApp-style web app on the iPhone. Each chat on the phone is one real Claude Code session running on the Mac, and each of those sessions is also a visible Terminal window on the Mac, so the same conversation can be continued at the desk or on the phone. Tapping "+" on the phone opens a new Terminal window on the Mac with Claude Code ready, starting in ~/Desktop/project/, so anything built lands in the project folder. When Claude wants to run a command, the phone shows Approve / Deny buttons.

When Luqman says "connect it back"

He means the iPhone can't reach claude-chat. Check in this order, fix what's broken, then confirm iphone183 is no longer offline in TS status. (Steps tested 2026-09-10 while healthy.)

  1. Server — launchctl list | grep claude-chat shows a PID, and curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:4477/ gives 200. If not: launchctl kickstart -k gui/$(id -u)/com.juslangit.claude-chat, then read data/server.log.
  2. Tailscale on the Mac — launchctl list | grep tailscaled shows a PID and TS status lists luqman-mac. If stopped: launchctl kickstart -k gui/$(id -u)/com.juslangit.tailscaled. If it says logged out: TS up --hostname=luqman-mac prints a link Luqman must open and sign in to.
  3. Serve — TS serve status shows https://luqman-mac.tail8806f8.ts.net → http://127.0.0.1:4477. If empty: TS serve --bg 4477.
  4. The iPhone — if iphone183 shows offline while 1–3 are fine, the fix is on the phone: open the Tailscale app and switch it on. Nothing on the Mac can do this.

Two traps found 2026-09-14:

  • Don't test with curl https://luqman-mac.tail8806f8.ts.net from the Mac. tailscaled runs with --tun=userspace-networking, so the Mac can't reach its own tailnet name or IP. It fails even when everything is healthy. Use TS ping iphone183 instead; a pong means the path is up.
  • Mac on the iPhone's Personal Hotspot (default gateway 172.20.10.1): the phone reaches the Mac only through the DERP relay (via DERP(sin), about 1 s), never directly. It works, just slower. Moving the Mac between networks drops open connections, so the phone app needs closing and reopening.

Not fixable from the Mac's side: Mac switched off (battery), Mac at the login screen after a restart (FileVault), home internet down — those need someone physically at the Mac. And the request itself can't come through claude-chat while claude-chat is the thing that's broken: it arrives from the Mac's Terminal or another channel (e.g. Claude Code Remote Control, if set up).

Patterns in use

Sending a message into the TUI reliably

When to use: any time text goes into a chat from outside. How: tmux load-buffer + paste-buffer -p (bracketed paste, so newlines don't submit), then check the text appears in the input box (the lines between the last two ──── rules, starting with ❯), then Enter, then check the box emptied. Retry each step. See sendText().

Knowing which chat a hook event belongs to

Each tmux session is started with -e CLAUDE_CHAT_ID=<id>; claude passes its environment to hook commands, so hook.mjs reads it and tells the server.

Following a chat through /clear and resume

The SessionStart hook carries transcript_path; if it differs from the stored one the server switches files (resume: reset the phone's history; clear: add a divider).
