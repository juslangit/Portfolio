Retopology

Retopo Kit is a Blender add-on that takes a sculpt to a game-ready asset in one press. Blender's own Object ▸ Quadriflow Remesh gives you quads and then stops — no UVs, no baked normal map, no LODs, one object at a time, and it asks for a face count nobody can guess. Retopo Kit keeps that remesher as its engine and supplies everything around it: a quad size asked for in centimetres, an automatic unwrap sized for the texture you will bake into, a normal bake with the ray distance worked out from the model itself, LODs named the way Unreal wants them, and a batch that runs the whole chain over a selection. It is for 3D artists doing the sculpt-to-game handoff, Luqman included — it is the second product he built to sell.

Why this project exists

Turning a sculpt into a game asset is a chain of chores, and Blender automates only the first link. So the artist guesses a face count, unwraps by hand, sets up a bake, gets the cage distance wrong, fixes the black patches, and then does all of it again for the next object. The work is well understood, repetitive and universally disliked — which is what makes it worth automating and worth paying for.

Two decisions follow from that problem. Quadriflow stays: rewriting a remesher is research-level C++ and a good free one already ships in the box. And the panel asks how wide a quad should be, because an artist can answer that, while nobody can answer "how many faces should this have".

What counts as "done"

All five steps of the chain work on real sculpts, in one press and over a selection: remesh by quad size, unwrap for the bake, bake the sculpt's detail into a normal map, batch the whole thing, and generate LODs with Unreal's naming. That is v1.0.0, released on GitHub on 2026-09-05 and verified on real sculpts. What is left before it can be sold is a listing, not code.

What is NOT in scope

  • Writing a remesher. Quadriflow is the engine and stays the engine.
  • Modifying the sculpt. The original is hidden, never altered or deleted; the low-poly arrives as a new LP_<name> object.
  • Hand-finishing. Seams are written back as real seams so an artist can move them, but the add-on does not pretend to make artistic decisions.
  • Anything outside Blender. The Unreal side of the handoff belongs to pipeline, which is a separate add-on.

01-idea.md · 5 sections

The idea

Problem

Turning a sculpt into a game-ready asset is a chain of chores, and Blender only automates the first link. Object ▸ Quadriflow Remesh gives you quads and then stops: no UVs, no baked normal map, no LODs, one object at a time, and it asks for a target face count that nobody knows in advance.

So the artist guesses a number, unwraps by hand, sets up a bake, gets the cage wrong, and repeats all of it for the next object.

Proposed solution

One press from sculpt to game-ready. Blender's Quadriflow stays as the engine — rewriting it is research-level C++ work and pointless when a good free one ships in the box — and the product is everything the box leaves out:

  1. Ask for a quad size in centimetres instead of a face count, and work the count out from surface area. An artist can answer "how big should each quad be"; nobody can answer "how many faces should this have".
  2. Unwrap the result automatically.
  3. Bake the sculpt's detail into a normal map, cage and all.
  4. Generate LODs.
  5. Do all of the above for a whole selection, not one object at a time.

Where the money is

Quad Remesher sells at $109 and only does the remeshing step, with a better algorithm. The gap it leaves — and that Blender leaves — is the rest of the chain. This product competes on the workflow, not on the algorithm, which is a fight a solo developer can actually win.

02-planning.md · 7 sections

Planning

Built in small steps. Each step is explained before it is written, works on its own, and Luqman tests it in Blender before the next one starts. This is deliberate: the Pipeline add-on was built as one finished piece in a single session and he could not explain it afterwards, which made it unsellable.

Step 1 — Remesh with a quad size ✅ done 2026-09-05

Ask for quad size in centimetres, work out the face count from surface area, run Quadriflow on a copy named LP_<name>, hide the original. Presets for hero prop, game prop and background.

Verified: a 32,256-face sphere became 2,919 faces, 100% quads, original untouched.

Step 2 — Automatic UV unwrap ✅ done 2026-09-06

Smart project with the angle limit exposed as a "seam angle", cuts written back as real seams so they can be edited, islands packed with a margin derived from the target texture size (4 pixels at 1K/2K/4K) so the bake cannot bleed. Runs automatically after the remesh, or on its own. Reports how much of the map is used.

Step 3 — Bake the detail ✅ done 2026-09-06

Tangent-space normal bake from sculpt to low-poly. Ray distance derived from the bounding box diagonal (2%) instead of being a number the artist has to guess. The low-poly records its source object at remesh time, so the bake needs no selection. Result is packed into the blend and wired through a Normal Map node into the Principled shader. Cycles is borrowed and restored.

Step 4 — Batch ✅ done 2026-09-06

Runs the chain over every selected sculpt. Failures are collected on a Result object rather than raised, so one bad mesh is reported and the run continues. Low-polys are skipped so a second run cannot nest prefixes. Both the single-object button and the batch go through one shared process() function.

Step 5 — LODs ✅ done 2026-09-06

LP_<name>_LOD0/1/2. Each level is decimated from the one above, never remeshed from the sculpt, so all levels keep the UVs and share the one baked normal map. Counts are reported in triangles because decimation converts quads to triangles.

All five steps are done

The chain runs end to end in one press. What remains is not features but proof: testing on real sculpts, then pricing and packaging.

Out of scope

  • Writing a new quad remeshing algorithm. Quadriflow ships free with Blender and beating it is a research project.
  • Manual retopology tools. RetopoFlow owns that space.

Gotchas / traps
ProblemCauseFix
Quadriflow refuses non-manifold meshes, and cancels rather than raising

bpy.ops.object.quadriflow_remesh returns {'CANCELLED'} instead of raising when it dislikes a mesh. Python code that ignores the return value carries on with an unremeshed copy — which then bakes a flat, useless normal map. The failure looks like success, which makes it far more dangerous than a crash. Always check the returned set.

What it actually rejects is non-manifold geometry: edges shared by three or more faces. It tolerates open boundaries fine. Three such edges in an 85,000-face sculpt are enough to make it refuse the entire mesh.

Repair attempts that do not work: voxel remeshing first still leaves 24-40 non-manifold edges; remove_doubles and dissolve_degenerate on voxel output make it dramatically worse (24 edges became 1,712).

What works: fall back to voxel remeshing entirely, sized from the same quad size the artist chose. Topology is less orderly, but it succeeds on anything.

Bake settings are inherited from the file

scene.render.bake.target persists in the .blend. A file where someone last baked vertex colours fails with "Mesh does not have an active color attribute", which points nowhere near the real cause. Set every bake setting explicitly rather than assuming defaults.

Artists arrive in Sculpt Mode

An operator whose poll demands context.mode == "OBJECT" greys out for anyone coming straight from sculpting, with no explanation shown. Accept any mode and call bpy.ops.object.mode_set yourself.

06-decisions.md · 4 sections

Decisions

D1 — Use Blender's Quadriflow as the engine (2026-09-05)

Context. Luqman asked for an add-on that automatically draws the new mesh, to sell. Blender already ships bpy.ops.object.quadriflow_remesh and voxel remesh for free, and the commercial competitor, Quad Remesher, sells at $109.

Decision. Do not write a new remeshing algorithm. Use Quadriflow underneath and sell the workflow around it: quad size in centimetres instead of face count, automatic UVs, automatic normal bake, batch processing and LODs.

Why. Field-aligned quad meshing is academic C++ research (Instant Meshes, QuadriFlow); a Python reimplementation would be far too slow to use, and shipping a compiled binary means cross-platform builds and macOS code signing — unreasonable for a first commercial product. Meanwhile the real pain is not the remesh, it is everything Blender leaves undone afterwards. Competing on workflow is a fight a solo developer can win; competing on the algorithm is not.

D2 — Build in small, individually testable steps (2026-09-05)

Context. The Pipeline add-on was built complete in one session. It passed 26 tests, but Luqman could not explain what it did, which made it impossible for him to demo, market or support — so it was released free instead of sold.

Decision. Each step of this add-on is explained in Blender terms before it is written, ships on its own, and gets tested by Luqman before the next step starts.

Why. For a product he intends to sell, his understanding of it is a hard requirement, not a nice-to-have.

D3 — Price at $29 and state both limitations in the listing (2026-09-06)

Context. Quad Remesher is $139.90 and has a better algorithm. Blender's Quadriflow is free. Retopo Kit sits between them: Blender's engine, plus the four steps neither of them automates.

Decision. $29, and the listing says outright that the algorithm is Blender's and that it is not deterministic.

Why. $29 is a fifth of Quad Remesher, which makes "just try it" easy, and above the $19 line where a listing starts reading as a weekend script. Stating the limits costs a few sales; discovering them after purchase costs refunds and one-star reviews, which on a small marketplace is much more expensive.

D4 — Ship despite Quadriflow's non-determinism (2026-09-06)

Context. The same sculpt returns different face counts run to run — 4,197, 3,131 and 1,094 across three identical runs — even with the seed pinned. It lives in Blender's C++ and cannot be fixed from an add-on.

Decision. Ship, document it in the README and the listing, and tell users to re-run if a result is too coarse.

Why. The alternative is not shipping. It is Blender's behaviour, visible to anyone using Quadriflow directly, and being first to say so reads as competence rather than as a defect being hidden.

  • Built the LOD step. The design point worth keeping: levels are decimated from the level above, never remeshed from the sculpt, because reducing an existing mesh preserves its UVs and therefore lets every level share the single baked normal map. Remeshing per level would need a texture each.

2026-09-06 — testing on a real sculpt

Downloaded Blender's own demo sculpt (01_sculpt_grab_silhouette.blend, an 85,319-face character) instead of testing against spheres. It found three faults within minutes, none of which primitives could ever have surfaced:

  1. Operators demanded Object Mode. The file is saved in Sculpt Mode — where every real user will be — so the buttons greyed out silently.
  2. Quadriflow cancels rather than raising, and the return value was ignored. The add-on produced an unremeshed copy presented as a low-poly, then baked a flat normal map from it. Success-shaped failure, the worst kind.
  3. The bake inherited the file's vertex-colour bake target and failed with a message pointing nowhere near the cause.

The interesting finding is why Quadriflow refuses: non-manifold edges, not holes. It tolerates open boundaries. Three three-face edges in 85,000 faces are enough. Voxel remeshing first does not fix it, and my attempted repair with remove_doubles and dissolve_degenerate made it far worse (24 bad edges to 1,712). The answer was to fall back to voxels entirely, driven by the same quad size, and say so in the report.

Result on the real character: 85,319 to 4,404 faces, 100% quads, UVs 58%, normal map carrying real detail, 3.3 seconds. 53 checks now pass.

Lesson for the whole project: every claim verified against primitives was worth very little. The first hour against real work found three shipping-blockers.
