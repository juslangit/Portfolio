Peta Lot Tanah

Peta Lot Tanah is an offline map of every cadastral land lot within 5 km of a point in Klang, Selangor — 64,770 of them — that opens straight from index.html with no server and no internet connection. Each lot is shaded by whether anything is built on it, by how big it is, and by the JUPEM area code that says whether it is town land or mukim land. It was built to answer a practical question about a piece of land by looking at the map rather than by reading a title search.

Why this project exists

A cadastral lot boundary is public information, but the official viewers are slow, online and awkward to compare lot against lot. This bakes one area's lots into a single data file and draws them locally, so the whole 5 km radius can be panned, filtered and recoloured instantly and without a connection.

What it covers

  • Centre: 3.042481, 101.414478 (Daerah Klang, Selangor), radius 5,000 m.
  • 64,770 lots, fetched a thousand at a time from PLANMalaysia iPLAN's LOT_10 service, which is the Selangor layer of the JUPEM NDCDB.
  • Buildings and land use from OpenStreetMap via the Overpass API, joined onto the lots so a lot can be called built or empty.
  • Satellite imagery underneath from Esri World Imagery, the one part that needs a connection.

The three colouring modes

  1. Built vs empty — red when a building is detected inside the lot, or the lot sits in residential, commercial or industrial land use; green when neither is true.
  2. Lot size — a threshold the viewer can move, defaulting to one acre.
  3. Town vs mukim — by JUPEM area code: 70 and above is bandar, 40–69 pekan, below 40 mukim.

01-idea.md · 1 sections

The idea

Show a piece of land the way a buyer actually asks about it: is anything on it, how big is it, and is it town land or mukim land? — and show it for every lot around it at the same time, so one lot can be judged against its neighbours.

The official sources answer those questions one lot at a time through a search form. This inverts that: fetch a whole radius once, join it to what OpenStreetMap knows about buildings and land use, and hand the result to a map that recolours instantly.

What it is not

It is a reference and planning aid, not a legal instrument. The README says so plainly: ownership, express conditions, restrictions in interest and official area must be confirmed through eTanah or the district land office. The lot boundaries are NDCDB geometry, simplified for drawing.

02-planning.md · 2 sections

Planning

v1 is done and in use. The scope was one radius, one state, three colouring modes.

Shape of the work

  1. fetch_lots.py pulls lot polygons from the iPLAN ArcGIS REST service in pages of 1,000, retrying with a widening delay, and writes data/lots_raw.json (28 MB).
  2. fetch_osm.py pulls buildings and land use for the same box from Overpass.
  3. build_data.py joins them, computes each lot's area and centroid with a shoelace sum in local metres, and emits data/lots.js (6.5 MB) — a compact payload the page can load as a plain script tag.
  4. index.html draws it with Leaflet and does all the filtering in the browser.

What would come next, if it is picked up again

  • Fix the hardcoded /Users/juslangit/peta-lot-tanah base path in the three scripts.
  • Another state is a one-line change: the service number in fetch_lots.py (LOT_01 Johor through LOT_11 Terengganu).
  • The README is in Malay, from before the move to English notes and interfaces.

04-methods.md · 3 sections

Methods

Opening it
open ~/Desktop/project/web/peta-lot-tanah/index.html

No server, no build step, no install. The satellite imagery needs a connection; the lots themselves do not.

Rebuilding the data
python3 fetch_lots.py && python3 fetch_osm.py && python3 build_data.py

Change LAT, LON and RADIUS_M in all three scripts first — and note that each also carries an absolute base path that predates the project's move, so fix that too.

Patterns in use

Vendored, not linked

Leaflet 1.9.4 sits in vendor/ rather than coming from a CDN, which is what lets the map open with no connection at all.

Data as a script, not as a fetch

data/lots.js assigns the lots to a global and is loaded with a <script> tag. A file:// page cannot fetch() a local JSON file without a server; a script tag can.

Geometry in local metres

Areas and centroids are computed with a shoelace sum after converting degrees to metres at this latitude (110,574 m per degree of latitude, 111,320 × cos(lat) per degree of longitude). Good enough over a 5 km radius and avoids a projection library.

Retry with a widening delay

The iPLAN service times out under load, so each page is attempted four times, waiting 3, 6, 9 and 12 seconds between tries. The run is logged to data/fetch.log.

06-decisions.md · 4 sections

Decisions

D-001 — Bake the data instead of running a server

Chosen: ship data/lots.js as a script the page loads. Over: a small API in front of the raw GeoJSON. Why: the map has to open from a double-click on a laptop with no connection. A file:// page cannot fetch a local JSON file, but it can load a script, so the data became a script. The cost is a 6.5 MB file and a rebuild whenever the area changes.

D-002 — Vendor Leaflet

Chosen: copy Leaflet 1.9.4 into vendor/. Over: the usual CDN tag. Why: same reason — offline. It also pins the version for good.

D-003 — Simplify the geometry at the source

Chosen: ask iPLAN for maxAllowableOffset=0.000004 and six-figure precision. Why: full-precision NDCDB polygons for 64,770 lots are far heavier than a browser wants to draw, and the difference is invisible at the zoom levels this map is used at.

D-004 — Judge "built" from two signals

Chosen: a lot counts as built if an OSM building falls inside it or it sits in built land use (residential, commercial, industrial and similar). Why: OSM building coverage in this area is incomplete, so buildings alone would paint developed neighbourhoods green. Land use fills the gaps at the cost of some false positives, which is the safer error for a first look at an area.
