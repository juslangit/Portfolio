Pipeline

Pipeline is a Blender add-on that batch-exports a scene to Unreal Engine with the naming, unit scale, pivots and collision meshes Unreal expects. It is the first digital product built to be sold online, chosen because it is pure code — no modelling or recording time — and because Luqman will use it himself when building the Malaysian environment asset packs planned as the next product.

Why this project exists

Every Blender-to-Unreal handoff repeats the same manual chores: apply transforms, rename to SM_/SK_, drop the pivot to the floor, keep UCX_ collision attached to the right mesh, then export objects one at a time. The work is well understood and universally hated, which makes it a good first product — small scope, obvious value, and an evergreen audience of Unreal developers and students.

Current state

  • v1.0.0 written and working: 12 registered classes, four export modes, FBX and glTF output, a validation pass, and a sidebar UI.
  • Blender 5.2.1 LTS installed via Homebrew on 2026-09-05.
  • 25 headless checks pass, including an FBX round trip that measures the re-imported mesh to confirm pivot placement, baked rotation, unit scale and mirrored normals.
  • The distributable zip installs and enables as a Blender extension. It is currently installed in the local Blender, so the Pipeline tab is live in the 3D viewport sidebar.
  • Not yet verified: how the exported files behave once imported into UE5.

01-idea.md · 6 sections

The idea

Problem

Getting assets from Blender into Unreal Engine is a chore that never goes away. Unreal expects specific naming (SM_, SK_), collision meshes named UCX_<Mesh>_<n>, clean 1,1,1 transforms, and pivots placed where the asset will be placed in the level. Blender provides none of this by default, so artists apply transforms by hand, rename objects one at a time, and run the FBX exporter once per asset. A scene of forty props is an afternoon of clicking, and any mistake surfaces only after the import into Unreal fails or looks wrong.

Proposed solution

A Blender sidebar panel that exports the whole scene in one press. It splits the export by collection, object, selection or scene; bakes transforms and modifiers on temporary copies so the working scene is never modified; re-origins each asset; keeps collision meshes attached to their owner; applies Unreal's naming convention; and validates the set first, refusing to export when two assets would overwrite each other or when a mesh has no UV map.

  • Formats: FBX and glTF (.glb)

04-methods.md · 4 sections

Methods

Baking a transform without operators

bpy.ops.object.transform_apply needs a valid context, a selection, and object mode. Writing the world matrix straight into the mesh data avoids all three:

matrix = obj.matrix_world.copy()
obj.data.transform(matrix)
if matrix.determinant() < 0.0:
    obj.data.flip_normals()   # negative scale would invert the faces
obj.matrix_world = Matrix.Identity(4)

The determinant check matters: a mirrored object exported without it arrives in Unreal with its faces inside out, which is one of the most common reports against competing exporters.

Surviving Blender version changes

The FBX and glTF exporters change their keyword arguments between releases. Rather than branching on bpy.app.version, build the full argument dictionary and filter it against the operator's own RNA:

valid = set(bpy.ops.export_scene.fbx.get_rna_type().properties.keys())
kwargs = {k: v for k, v in kwargs.items() if k in valid}
Applying modifiers without destroying skinning

bpy.data.meshes.new_from_object(evaluated_object, depsgraph=depsgraph) bakes the whole modifier stack — including the armature modifier, which freezes the pose into the mesh. Meshes with an armature modifier must therefore keep their stack and be copied rather than evaluated, leaving the deformation to Unreal.

Nested collections

collection.all_objects includes everything in child collections. When exporting one file per collection, a parent collection would re-export everything its children already wrote. The rule used here: a collection with children exports only its direct objects, one without children exports all_objects.

06-decisions.md · 5 sections

Decisions

D1 — Build the Blender add-on first, not the asset pack (2026-09-05)

Context. Eight digital product ideas were on the table: Malaysian environment asset packs, a retro-console shader kit, a printable handheld console kit, a Blender-to-UE5 course, a lecturer toolkit, an archviz conversion pack, a VR starter template, and this exporter.

Decision. Build the exporter add-on first.

Why. It is the only one that is pure code, so it could be built to a finished v1.0 immediately with no modelling or recording time. It is evergreen, needs no new content to keep selling, and it will be used in-house to build the asset packs that are the intended second product — which doubles as the honest quality test.

Rejected because: the asset packs need weeks of modelling before anything is sellable; the course and lecturer toolkit need material written and recorded.

D2 — Ship as a single folder carrying both bl_info and blender_manifest.toml (2026-09-05)

Context. Blender 4.2 introduced the extensions system and deprecated legacy bl_info add-ons, but a large share of users are still on 3.6 LTS and 4.1.

Decision. Ship one zip containing a package folder that has both the legacy bl_info dictionary and an extension manifest.

Why. One download works on Blender 3.6 through 5.x. Customers on older versions are exactly the ones least likely to debug an install failure, and a support ticket costs more than the duplicated metadata.

D3 — Bake on temporary copies rather than applying to the scene (2026-09-05)

Context. Applying transforms and modifiers is required for a clean Unreal import, but doing it to the user's objects is destructive and undo-dependent.

Decision. Duplicate the objects into a temporary collection, bake the world matrix into the mesh data directly (rather than through bpy.ops.transform_apply), export, then delete the copies and their orphaned data.

Why. It is non-destructive, it does not depend on operator context or the undo stack, and negative scale can be detected from the matrix determinant and corrected with a normal flip — which the operator path handles inconsistently.

D4 — Filter exporter arguments against the operator's RNA at call time (2026-09-05)

Context. Blender's FBX and glTF exporters gain and lose keyword arguments between releases, which is the usual reason an add-on breaks on a new version.

Decision. Build the full argument dictionary, then drop any key the running Blender's operator does not declare.

Why. One code path supports 3.6 through 5.x without version branches, and a new Blender release degrades gracefully instead of raising a TypeError.

D5 — Release Pipeline free rather than sell it (2026-09-05)

Context. The add-on was finished, tested to 26 checks and had a complete store listing written, priced at $19 with Blender Market as the storefront. Luqman then said he still did not understand the add-on.

Decision. Release it free and open source under GPL-3.0, repository public, and move on to a new project.

Why. A product the owner cannot explain is one he cannot demo, market or support. Selling it would have created a support obligation he was not equipped to meet, and a refund-and-bad-review risk that outweighed the few hundred dollars the launch was realistically worth. Released free it still carries his name, still feeds his portfolio, and costs him nothing to maintain.

Wider lesson recorded. The failure was in delivery, not domain — a finished black box built at speed. His next project is also a Blender add-on, so the answer is to build it with him and explain as it goes, not to avoid code.

07-references.md · 3 sections

References

Unreal conventions

  • Static mesh SM_, skeletal mesh SK_, animation A_
  • Collision: UCX_ convex, UBX_ box, USP_ sphere, UCP_ capsule, named UCX_<MeshName>_<number>
  • 1 Blender metre = 100 Unreal units (centimetres)

Blender API

  • bpy.data.meshes.new_from_object — evaluate an object with its modifiers applied
  • bpy.ops.export_scene.fbx.get_rna_type().properties — the exporter's real argument list
  • Blender extensions manifest — blender_manifest.toml, required from 4.2

Competitors to study before pricing

  • Epic's Send to Unreal (free, official)
  • The various paid batch exporters on Blender Market
