Why this project exists

Luqman asked on 2026-09-17 for a way to make money on YouTube, generated and uploaded end to end. The honest position was put to him first: Shorts ad revenue alone is a poor business. Full monetisation needs 1,000 subscribers and 10 million Shorts views in 90 days — doubling to 20 million on 2027-02-01 — and Shorts RPM is roughly $0.03–0.08 per thousand views, so even hitting that bar pays a few hundred dollars. A funnel to something he sells (the Pipeline and Retopology add-ons) was recommended instead.

He chose a general faceless facts channel anyway, with a synthetic voice and API upload. That is what was built. The recommendation stands and is recorded in D-001 in case the channel is ever repositioned.

What counts as "done"

One command produces a publishable Short with no manual editing, the facts in it are sourced, and getting it onto YouTube takes under a minute of Luqman's time. The first four are met. The last is capped by YouTube's API audit (D-003).

Where it stands

Ten videos are built and sitting in out/. None has been published, and no YouTube channel has been confirmed to exist yet. Nothing about the channel's performance is known, because nothing has been posted.

02-planning.md · 3 sections

Planning

Scope of v1 (built 2026-09-17)

In:

  • A sourced topic bank as plain JSON, one entry per video
  • Script generation with hook variation, so videos are not one template
  • Narration from macOS say with measured per-line timing
  • 1080x1920 video with word-level caption highlighting, six colour palettes
  • Title, description with sources, and tags
  • A copy-paste sheet for manual publishing
  • A finished YouTube Data API uploader

Out, deliberately:

  • Stock footage and AI imagery. Motion typography needs no API, no credits and no licence risk. OpenArt credits are never spent without Luqman's approval.
  • Thumbnails. Shorts use a frame from the video, and the hook frame is already designed to work as one.
  • Scheduling. Pointless until M5 proves the format on a real channel.

What has to happen next

  1. Confirm a YouTube channel exists. Never established during the build.
  2. Publish one video by hand and watch the retention graph. The first three seconds are the whole game; if viewers drop before the first fact, the hooks are the problem, not the facts.
  3. Apply for the API compliance audit in parallel (D-003).
  4. Grow the bank toward 30 topics only once the format has been shown to work. Building 30 videos nobody has watched would repeat the mistake M5 exists to prevent.

The thing to keep in view

This channel can only earn from ads, and the bar is 1,000 subscribers plus 10 million Shorts views in 90 days — 20 million from 2027-02-01 — at roughly $0.03–0.08 per thousand views. It is a volume business with a low ceiling.

The pipeline itself is content-agnostic: the bank is a JSON file. If the facts channel stalls, pointing it at Blender and 3D tips that sell Pipeline and Retopology is a content job, not a rebuild. That option was recommended first (D-001) and stays open.

04-methods.md · 6 sections

Methods

Daily routine
cd ~/Desktop/project/ai/shorts-factory
python3 src/make.py            # builds the next unused topic
python3 src/publish_sheet.py   # prints the Studio fields, copies the description,
                               # and opens Finder at the video

Then drag the file into youtube.com/upload and paste. Set Not made for kids.

out/made.json records what has been built so make.py never repeats a topic. Delete an entry from that list to rebuild one.

Measuring speech instead of estimating it

say gives no word timings, so guessing where words land would put the captions out of sync. Instead voice.py renders each line to its own file, measures it with ffprobe, then lays the clips out with adelay at known offsets. The caption timeline is derived from audio that actually exists, so word highlighting is exact. Word positions within a line are then spread by character count, which is close enough at this speaking rate.

say infers its output format from the file extension: --data-format=LEI16@22050 works with a .wav output but fails with .aiff, because AIFF is big-endian. That cost a failed run on the first attempt.

Why frames are drawn in Python

The ffmpeg here has no drawtext and no subtitles filter — it was built without libfreetype and libass. Check with ffmpeg -filters | grep drawtext before assuming any text filter exists. render.py draws every frame with PIL and pipes raw RGB24 into ffmpeg, which only encodes. See D-004.

Layout rules that had to be learnt
  • The Shorts player covers the edges. Content stays between y=360 and y=1440, and the progress bar sits at y=1470 to clear the button column.
  • Highlighted words need more spacing than the font provides. The highlight box sticks out past the glyphs by pad_x on each side, so the gap between words must clear 2 * pad_x or the boxes collide with their neighbours. The two are now tied together in code rather than tuned separately — the first two attempts both looked cramped because they were set independently.
  • Captions auto-fit. _fit() shrinks the font until the wrapped block fits its box. Without it, a four-line caption ran straight through the source credit underneath.

Always render a contact sheet and look at it before believing a layout:

for t in 1.5 5.5 9.5 14 18.5 23; do
  ffmpeg -y -ss $t -i out/<id>/video.mp4 -frames:v 1 -vf scale=405:-1 /tmp/f_$t.png
done
Better narration, free

Only the basic macOS voices are installed. System Settings → Accessibility → Spoken Content → System Voice → Manage Voices downloads the Premium voices, which are far better, cost nothing, and need only the exact voice name put into config.json. This is the single largest quality gain available to the project.

Note that global/stack.md claims an ELEVENLABS_API_KEY exists. It does not — it is not in ~/.claude/.env. Verify a key is present before planning on it.

Adding topics

One entry in topics/bank.json = one video. Every beat needs a real source (D-002). key is the short phrase burned large on screen — keep it to one to three words. make.py refuses a script that would run past the Shorts limit rather than building a video YouTube would reject.

06-decisions.md · 5 sections

Decisions

D-001 — A general facts channel, over a funnel to his own products
  • Date: 2026-09-17
  • Status: active
  • Context: Luqman asked for a channel to make money from. The arithmetic was put to him before anything was built: full Shorts monetisation needs 1,000 subscribers plus 10 million Shorts views in 90 days, rising to 20 million on 2027-02-01, at an RPM of roughly $0.03–0.08. Ten million views is therefore worth about $300–800.
  • Options considered:
OptionProsCons
Faceless general factsFully automatable, no input from him at allSaturated; builds nothing he owns; ad revenue only
His own AI/game buildingContent is a by-product of work he already does; feeds portfolio and freelance leadsNeeds screen recording, less automatable
Blender/3D tipsSells Pipeline and Retopology directly; ~50 buyers beats 10M viewsHe must author every tip
  • Decision: Faceless general facts, synthetic voice.
  • Reason: Luqman's explicit choice after the alternatives and the arithmetic were laid out. He wanted the version that needs nothing from him.
  • Consequences / trade-offs: The channel earns only from ads, so it needs enormous scale to pay anything. The pipeline itself is content-agnostic — the bank is a JSON file — so repointing it at Blender tips later is a content job, not a rebuild.
D-002 — Every fact carries a source, on screen and in the description
  • Date: 2026-09-17
  • Status: active
  • Context: A generator that invents facts is both dishonest and a policy risk. YouTube demotes mass-produced, repetitive, low-originality content.
  • Decision: topics/bank.json requires a source string on every beat. It is burned onto the frame under the caption and listed in the description.
  • Reason: It is the difference between a reference-backed channel and the scraped-slop category. It also means a wrong fact can be traced and fixed rather than argued about.
  • Consequences / trade-offs: Writing a topic takes longer, because the facts have to be checked before they can be entered.
D-003 — Publish by hand now; keep the API uploader for after the audit
  • Date: 2026-09-17
  • Status: active
  • Context: Luqman chose API upload. Checking the API terms before building it turned up a blocker: YouTube permanently locks every video uploaded through the Data API by an unverified API project to private, with no appeal, for any project created after 2020-07-28. Separately, while an OAuth consent screen sits in Testing, Google expires refresh tokens after 7 days, so the automation would break weekly regardless.
  • Options considered:
OptionProsCons
API upload nowZero effortEvery video locked private forever — useless
Manual upload via StudioVideos are actually public~30 seconds per video
Wait for the audit before launchingFully automatic when it startsWeeks of not posting; an empty channel weakens the audit application
  • Decision: Build both. Ship publish_sheet.py to make manual publishing a copy-paste job, and keep upload.py finished and waiting for the audit.
  • Reason: The goal is public videos, and manual upload is the only route to one today. Posting by hand also builds the channel history that helps the audit application succeed.
  • Consequences / trade-offs: Luqman is in the loop once per video until the audit passes. upload.py is written but unexercised against the live API.
D-004 — Draw every frame in Python rather than using ffmpeg filters
  • Date: 2026-09-17
  • Status: active
  • Context: The Homebrew ffmpeg 9.0.1 on this Mac is built without libfreetype and libass, so both drawtext and subtitles are missing. Text cannot be burned in with a filter at all.
  • Decision: Generate each frame with PIL and numpy and pipe raw RGB into ffmpeg, which only encodes.
  • Reason: Forced by the missing filters, but it is the better design: it is what makes per-word highlight boxes, auto-fitting captions and pop-in animations possible. A filtergraph could not have done the word highlighting.
  • Consequences / trade-offs: Render time is roughly real-time (28s for a 24s video) rather than near-instant. Irrelevant at one video a day.
D-005 — macOS say for narration, not ElevenLabs
  • Date: 2026-09-17
  • Status: active
  • Context: global/stack.md lists an ElevenLabs Starter plan with ELEVENLABS_API_KEY. That key is not in ~/.claude/.env — the stack note is stale. macOS say was the remaining option and costs nothing.
  • Decision: Narrate with say, each line rendered separately so its exact duration can be measured with ffprobe. The voice name is a config field.
  • Reason: Free, offline, no quota, and per-line measurement gives exact caption timing rather than estimated timing.
  • Consequences / trade-offs: Only the basic voices are installed, so quality is below ElevenLabs. Downloading a macOS Premium voice is free and is the largest available quality gain — see 04-methods.md.

07-references.md · 3 sections

References

The rules that shaped the build

  • Videos locked as private — YouTube Help — API uploads from unverified projects are locked private permanently, no appeal.
  • YouTube Data API revision history — the restriction applies to projects created after 2020-07-28.
  • videos.insert — 1,600 quota units per upload against a 10,000/day default.
  • Google OAuth refresh token lifetime — refresh tokens expire after 7 days while the consent screen is in Testing.

The economics

  • YouTube Partner Program eligibility — 500 subs + 3M Shorts views in 90 days for fan funding; 1,000 subs + 10M for ad revenue; doubling to 20M on 2027-02-01.
  • Shorts RPM by niche, 2026 — roughly $0.03–0.08 per thousand views; finance and tech skew higher, broad entertainment lower, and non-US audiences much lower.

Sources used in the topic bank

Every fact in topics/bank.json carries its own source field. The bodies used so far: NASA, NOAA, USGS, US EPA, US NRC, the Natural History Museum (London), the British Antarctic Survey, Britannica, Smithsonian Magazine, and the Société d'Exploitation de la Tour Eiffel.
